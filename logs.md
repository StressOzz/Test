## 🧠 Как устроены логи в OpenWrt

- По умолчанию системный лог хранится **в оперативной памяти** (кольцевой буфер).
- **После перезагрузки лог полностью стирается.** Поэтому нельзя «посмотреть, что было перед ребутом», если запись в файл или на ПК не была включена заранее.
- Буфер небольшой: при его заполнении старые записи затираются новыми.
- В LuCI лог есть в **Status → System Log** и **Status → Kernel Log**, но там видно только то, что произошло с момента последнего включения.

## 👀 Просмотр текущего лога

```sh
logread                 # весь системный лог
logread -l 50           # последние 50 строк
logread -f              # лог в реальном времени (выход — Ctrl+C)
logread -e zapret       # только строки, где встречается "zapret"
logread -e nfqws        # только строки nfqws
logread | grep -i error # поиск ошибок
```

Лог ядра (драйверы, Wi-Fi, память, сбои):

```sh
dmesg                   # весь лог ядра с текущей загрузки
dmesg | tail -n 50      # последние 50 строк
```

Сколько роутер работает с последнего включения:

```sh
uptime
```

## 💾 Сохранение лога в файл (переживает перезагрузку)

### Включение

```sh
uci set system.@system[0].log_file='/root/system.log'
uci set system.@system[0].log_size='512'
uci commit system
/etc/init.d/log restart
```

| Параметр | Что значит |
|---|---|
| `log_file` | путь к файлу лога |
| `log_size` | максимальный размер файла в KiB. Когда файл достигает лимита, он переименовывается в `system.log.old` и запись начинается заново |

> ⚠️ **Не указывайте путь в `/tmp`** — `/tmp` находится в оперативной памяти и очищается при перезагрузке.
> Подходят `/root/...` (флеш-память роутера) или USB-флешка, например `/mnt/sda1/system.log`.

> ⚠️ **Флеш-память роутера имеет ограниченный ресурс записи.** Включайте запись в `/root` только на время диагностики (несколько дней), потом отключайте. Для постоянного логирования лучше USB-флешка или [remote syslog](#-отправка-лога-на-компьютер-remote-syslog).

### Проверка, что лог пишется

```sh
uci show system | grep log_
ls -l /root/system.log
tail -n 20 /root/system.log
```

### Просмотр после перезагрузки

```sh
tail -n 100 /root/system.log        # последние 100 строк
cat /root/system.log                # весь файл
cat /root/system.log.old            # предыдущая часть (если файл уже ротировался)
grep -i -E "error|fail|oom|panic|killed" /root/system.log
```

### То же самое через LuCI

**System → System → вкладка Logging**:
- **Write system log to file** → `/root/system.log`
- **System log buffer size** → `512`
- **Save & Apply**

> ℹ️ Страница **Status → System Log** в LuCI показывает только лог из памяти и **не читает файл**. Сохранённый файл смотрите по SSH или скачайте на ПК.

### Сохранить лог вручную перед плановой перезагрузкой

```sh
logread > /root/log_before_reboot.txt
dmesg  > /root/dmesg_before_reboot.txt
```

## 🖥️ Отправка лога на компьютер (remote syslog)

Лог отправляется по сети на ПК в реальном времени. Флеш роутера при этом не изнашивается, а лог сохраняется, даже если роутер зависнет намертво.

### 1. Подготовка ПК

- Установите любой syslog-сервер. Для Windows подойдёт, например, бесплатный **Visual Syslog Server**.
- Разрешите в брандмауэре Windows входящие подключения **UDP 514**.
- Узнайте IP компьютера в локальной сети (`ipconfig`), например `192.168.1.100`.
- Желательно закрепить за ПК постоянный IP (статическая аренда DHCP в **Network → DHCP and DNS → Static Leases**).

### 2. Настройка роутера

```sh
uci set system.@system[0].log_ip='192.168.1.100'
uci set system.@system[0].log_port='514'
uci set system.@system[0].log_proto='udp'
uci commit system
/etc/init.d/log restart
```

Проверка — отправьте тестовое сообщение, оно должно появиться в программе на ПК:

```sh
logger "Тест remote syslog"
```

### Без установки программ

Можно просто держать открытым окно с логом в реальном времени и сохранять его в файл на ПК (команда выполняется **на компьютере**, в PowerShell или CMD):

```powershell
ssh root@192.168.1.1 "logread -f" > router_log.txt
```

Минус: если ПК уснёт или SSH-сессия оборвётся, запись прекратится.

## 📥 Как скачать лог на ПК

Команды выполняются **на компьютере** (PowerShell / CMD / терминал Linux).

Сохранить текущий лог в файл одной командой:

```powershell
ssh root@192.168.1.1 "logread" > router_log.txt
ssh root@192.168.1.1 "dmesg" > router_dmesg.txt
```

Скачать сохранённый файл лога:

```powershell
scp -O root@192.168.1.1:/root/system.log .
```

> ℹ️ Ключ `-O` нужен, потому что в OpenWrt обычно нет SFTP-сервера, а новые версии `scp` по умолчанию используют SFTP.

Также можно использовать **WinSCP** (протокол **SCP**, не SFTP): открыть `/root/` и скачать `system.log`.

## 🔍 Поиск причины перезагрузки

### Шаг 1. Проверить лог краха ядра (pstore)

На некоторых роутерах ядро сохраняет лог последнего сбоя в специальную область памяти, которая переживает перезагрузку:

```sh
ls /sys/fs/pstore/
cat /sys/fs/pstore/* 2>/dev/null
```

Если там есть файлы (например, `dmesg-ramoops-0`) — это лог **kernel panic**, из-за которого роутер перезагрузился. На большинстве роутеров папка пустая или отсутствует — это нормально.

### Шаг 2. Проверить, не перезагружается ли роутер по расписанию

```sh
cat /etc/crontabs/root
grep -rn "reboot" /etc/crontabs/ /etc/rc.local /etc/hotplug.d/ 2>/dev/null
```

### Шаг 3. Включить запись лога и дождаться следующей перезагрузки

Используйте [запись в файл](#-сохранение-лога-в-файл-переживает-перезагрузку) или [remote syslog](#-отправка-лога-на-компьютер-remote-syslog). После перезагрузки смотрите **последние строки** перед обрывом лога.

### Шаг 4. Расшифровать, что найдено

| Что видно в логе перед перезагрузкой | Вероятная причина |
|---|---|
| `Out of memory`, `oom-killer`, `Killed process` | закончилась оперативная память (тяжёлые службы: nfqws, AdGuard Home, большие списки и т.п.) |
| `Kernel panic`, `Oops`, `BUG:`, `Call Trace` | сбой ядра или драйвера (часто Wi-Fi или USB) |
| `watchdog` | система зависла, сработал аппаратный сторожевой таймер |
| `reboot` от скрипта, cron или `procd` | перезагрузку запустила программа или расписание |
| Лог просто обрывается без ошибок | чаще всего **питание**: слабый или неисправный блок питания, перегрев, просадка напряжения |

## 🛠️ Полезные команды для диагностики

```sh
free                          # свободная оперативная память
cat /proc/meminfo             # подробно о памяти
top -n 1                      # какие процессы грузят CPU и память
df -h                         # свободное место на флеше и в /tmp
cat /proc/loadavg             # средняя нагрузка
ubus call system board        # модель роутера и версия OpenWrt
ubus call system info         # uptime, память, нагрузка
```

### Уменьшить «шум» от cron в логе

Если лог забит сообщениями cron о каждом запуске задачи:

```sh
uci set system.@system[0].cronloglevel='9'
uci commit system
/etc/init.d/cron restart
```

## ❌ Отключение записи лога

Отключить запись в файл и удалить его:

```sh
uci delete system.@system[0].log_file
uci commit system
/etc/init.d/log restart
rm -f /root/system.log /root/system.log.old
```

Отключить remote syslog:

```sh
uci delete system.@system[0].log_ip
uci delete system.@system[0].log_port
uci delete system.@system[0].log_proto
uci commit system
/etc/init.d/log restart
```

Очистить файл лога, не отключая запись:

```sh
> /root/system.log
```
